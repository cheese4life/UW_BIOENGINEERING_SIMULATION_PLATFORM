Functions

Connect ()
Establish a connection to the device.
Initialize ()

Initialize the device and makes it ready for use.

This function does not need a Wait call after it - this function blocks until the device is initialized.

In the case of an axis this involves:

  • Establishing a connection to the hardware.
  • Performing Analog Calibration.
  • Performing Commutation.
Wait ([timeout_ms=DefaultTimeout_ms])
Wait for the previous asynchronous action on this device to complete.

Each device can have only one action in progress at a time - starting another action while one is already in progress raises an error. Wait waits for the currently-running action to finish before returning, or checks the last action's status if it has already completed. After Wait returns, another action can be started.

Changes to device settings are also asynchronous, and require Wait to be called to block until the setting has actually been set.

Parameters:

  • timeout_ms int The length of time to wait from when this function is called before raising a timeout error. (default DefaultTimeout_ms)

Raises:

An error is raised if the timeout expires before the action completes, the previous asynchronous action was EStopped or if the action or setting change being waited on fails for any other reason.

Usage:

    Device.PerformAction()

-- The function above returns immediately, but the action is still in progress.
-- We can call Wait() to block until the action is actually finished.
Device.Wait()
Shutdown ()
Shutdown the device in preparation for power off. Once a device has been shutdown, it will accept no further commands. If there is a connection associated with this device and this is the last device using the connection, the connection will be closed.

Async:

    This function call is asynchronous and must be followed up with a call to Wait.

Usage:

    Device.Shutdown()
Device.Wait()
EStop ()
Perform an emergency stop of the device. This will immediately halt any motion (e.g. an abrupt stop will be performed for an axis device) and return the device to a safe, passive state (e.g. for an axis device this means the operating mode is set to disable the axis, motor output, current control, position loop, and trajectory). The next call to Wait() on this device will raise an error, indicating the device has been EStopped and the command in progress was interrupted. Alternatively, EStopWait() can be called to wait for the estop to complete without throwing an exception. Initialize() must be called on this device before it will accept further commands.

Async:

    This function call is asynchronous and must be followed up with a call to EStopWait.

See also:

    EStopWait

Usage:

    Device.EStop()
Device.EStopWait()

MoveContinuous (position, acceleration, velocity, deceleration)
Moves axis to the specified absolute position in selected units (mm, um, or nm), without needing to wait for an existing move to complete.

It uses the supplied trajectory parameters (velocity, acceleration, deceleration), not the currently selected move profile. The trajectory parameters can also be modified during a move. Note that only trapezoidal moves are supported for continuous moves, not s-curve moves, hence the lack of a jerk parameter.

Async:

    This function call is asynchronous and must be followed up with a call to Wait.

Parameters:

  • position number Value of the absolute coordinate to move to in selected units (mm, um, or nm).
  • acceleration number Maximum acceleration to be set in selected units (mm/s^2, um/s^2, or nm/s^2).
  • velocity number Maximum velocity to be set in selected units (mm/s, um/s, or nm/s).
  • deceleration number Maximum deceleration to be set in selected units (mm/s^2, um/s^2, or nm/s^2).

Usage:

    -- Perform the first move to position 20.
XAxis.MoveContinuous(20, 500, 100, 500)
- Wait half a second
lock.sleep_ms(500)

- Change the target position back to position 10.
Axis.MoveContinuous(10, 500, 100, 500)
Axis.Wait()

Stop ()
Stop the current movement action in a controlled manner. Will stop the current move action and return immediately. The original move command will complete once the axis has come to a halt. If there is no movement in progress, the operation will complete without error. Wait() must still called after issuing a Stop() to wait for the axis to come to a halt. Unlike EStop(), the Stop() command does not require the axis to be re-initialized.

Async:

    This function call is asynchronous and must be followed up with a call to Wait.

Usage:

    -- Set the acceleration, deceleration, velocity and jerk to values
-- suitable for a move.
XAxis.SelectMoveProfile('XAxisStandardMoveProfile')
XAxis.Wait()

-- Start a move.
XAxis.MoveAbsolute(50)

-- Some time later, stop the move.
XAxis.Stop()
XAxis.Wait()

-- The axis is now stationary.

  • Acceleration
  • Velocity
  • Jerk
  • Deceleration

EnableTraceCapture (traceTrigger, period, variables)
Enable capture of trace data.

If the trigger is 'OnMotionStart', trace capture will be automatically started when the next move begins and stopped once the move completes. If the trigger is 'OnMotionStartNoEnd', trace capture will be automatically started when the next move begins and must be stopped by calling StopTraceCapture(). If the trigger is 'Immediate', trace capture will be started immediately and must be stopped by calling StopTraceCapture().

Async:

    This function call is asynchronous and must be followed up with a call to Wait.

Parameters:

  • traceTrigger string Trigger to start the trace capture (e.g. 'Immediate', 'OnMotionStart' or 'OnMotionStartNoEnd').
  • period integer Period at which the data is sampled in terms of the motion chip cycles (e.g. 1 = every cycle).
  • variables table A list of variables to capture. Up to 4 variables can be captured.

Usage:

    local traceVariables = {"CommandedVelocity", "PositionError", "CommandedPosition"}
XAxis.EnableTraceCapture("OnMotionStart", 10, traceVariables)
XAxis.Wait()

XAxis.MoveRelative(1)
XAxis.Wait()

XAxis.SaveTraceCapture("[ProgramDataFolder]/trace1.csv")

NEnableTraceCapture (traceTrigger, traceProfile)
Enable capture of trace data using a named trace profile defined in configuration.

If the trigger is 'OnMotionStart', trace capture will be automatically started when the next move begins and stopped once the move completes. If the trigger is 'OnMotionStartNoEnd', trace capture will be automatically started when the next move begins and must be stopped by calling StopTraceCapture(). If the trigger is 'Immediate', trace capture will be started immediately and must be stopped by calling StopTraceCapture().

Async:

    This function call is asynchronous and must be followed up with a call to Wait.

Parameters:

  • traceTrigger string Trigger to start the trace capture (e.g. 'Immediate', 'OnMotionStart' or 'OnMotionStartNoEnd').
  • traceProfile string The name of the trace profile section defined in configuration. This profile will specify the period and up to 4 trace variables.

Usage:

    XAxis.NEnableTraceCapture("OnMotionStart", "CommandedVelocityTraceProfile")
XAxis.Wait()

XAxis.MoveRelative(2)
XAxis.Wait()

XAxis.SaveTraceCapture("[ProgramDataFolder]/trace2.csv")
XAxis.Wait()
StopTraceCapture ()
Stop the capture of trace data. This will stop any trace capture currently in progress.

If the trigger supplied to EnableTraceCapture() was OnMotionStart or OnMotionStartNoEnd and a move has not started, this will cancel the request to capture trace data on the next move.

Async:

    This function call is asynchronous and must be followed up with a call to Wait.

Usage:

    XAxis.NEnableTraceCapture("Immediate", "CommandedVelocityTraceProfile")
XAxis.Wait()

EnableTriggerOnPosition (startPosition, endPosition, increment, isBidirectional, pulseWidthNs)
Enable trigger on position (TOP). TOP will generate a GPIO pulse every 'increment' of travel while in the window specified by 'startPosition' and 'endPosition'.

When using this feature with a SmartStageXY or SmartStageLinear, the GpioConfiguration in Instrument.cfg must be set to PMDGpioConfiguration::S2 (the default).

Async:

    This function call is asynchronous and must be followed up with a call to Wait.

Parameters:

  • startPosition number Position at which to start generating pulses in selected units (mm, um, or nm).
  • endPosition number Position at which to stop generating pulses in selected units (mm, um, or nm).
  • increment number Generate a pulse every 'increment' of travel in selected units (mm, um, or nm).
  • isBidirectional boolean If true, pulses will also be generated when moving from endPosition back to startPosition. If false, pulses will only be generated when moving from startPosition to endPosition.
  • pulseWidthNs number The width of the pulse to generate at each position in nanoseconds.

Usage:

    XAxis.NMoveAbsolute("NegativeLimit")
XAxis.Wait()

XAxis.EnableTriggerOnPosition(5, 10, 0.1, false, 100000)
XAxis.Wait()

Enable trigger on position (TOP). TOP will generate a GPIO pulse every 'increment' of travel while in the window specified by 'startPosition' and 'endPosition'.

When using this feature with a SmartStageXY or SmartStageLinear, the GpioConfiguration in Instrument.cfg must be set to PMDGpioConfiguration::S2 (the default).

Async:

    This function call is asynchronous and must be followed up with a call to Wait.

Parameters:

  • startPositionName string Named position at which to start generating pulses.
  • endPositionName string Named position at which to stop generating pulses.
  • namedDistance string Generate a pulse every 'namedDistance' of travel.
  • isBidirectional boolean If true, pulses will also be generated when moving from endPosition back to startPosition. If false, pulses will only be generated when moving from startPosition to endPosition.
  • pulseWidthNs integer The width of the pulse to generate at each position in nanoseconds. The actual pulse width is a value rounded to the nearest practicable value, which must be a multiple of 50ns and less or equal to 204,800 ns. It's ignored by version 1.2 and lower of the PMD motion control firmware.

SetDigitalOutputTrigger (trigger)

Enable / disable a digital output (AxisOut1) trigger based on the axis motion.

When using this feature with a SmartStageXY or SmartStageLinear, the GpioConfiguration in Instrument.cfg must be set to PMDGpioConfiguration::S2 (the default).

Possible triggers include:

 Disabled         - Digital output is set low and triggers are disabled (i.e. the digital output state is not affected by the axis state).
 InMotion         - The digital output will be set high whenever the axis is in motion.
 MotionComplete   - The digital output will be set high whenever the axis completes a move.
 AtMaxVelocity    - The digital output will be set high when the axis reaches maximum velocity during its move.
 Immediate        - The digital output will be set high immediately (i.e. the digital output is directly controlled by software).

Async:

    This function call is asynchronous and must be followed up with a call to Wait.

Parameters:

  • trigger string Specifies a trigger (see above) on which to set the digital output.

Usage:

    local clock = require 'lua_clock'

-- Enable a digital output trigger that will set the digital output (AxisOut1) high whenever axis motion completes.
XAxis.SetDigitalOutputTrigger("MotionComplete")
XAxis.Wait()

-- Perform a 2mm move. The digital output will be set when the move completes.
XAxis.MoveRelative(2);
XAxis.Wait()
-- Disable the digital output trigger.
XAxis.SetDigitalOutputTrigger("Disabled")
XAxis.Wait()

-- Turn on the digital output immediately
XAxis.SetDigitalOutputTrigger("Immediate")
XAxis.Wait()

-- Wait a couple seconds
clock.sleep_ms(2000)

-- Disable the digital output trigger.
XAxis.SetDigitalOutputTrigger("Disabled")
XAxis.Wait()

Returns a table of named positions for this axis.

The keys of the table are the position names and the values are the absolute positions in (mm, um, or nm).

  • NamedPositions table readonly

Usage:

--
-- [XAxisNamedPositions]

-- SlideLoad=5000

-- Retrieve the table of named positions.

NamedMoveProfiles
Returns a table of move profiles for this axis.

The keys of the table are the position names and the values are a a table with all the parameters of that move profile.

  • NamedMoveProfiles table readonly

Usage:

    -- For this move profile configuration in the instrument configuration:
-- [XAxis_Device]
-- Type=AxisDevice
-- NamedMoveProfiles=XAxisHomingProfile,XAxisMoveProfile
--
-- [XAxisHomingProfile]
-- Acceleration=2000000
-- Deceleration=2000000
-- Velocity=1000
-- Jerk=0
      --
-- [XAxisMoveProfile]
-- Acceleration=2000000
-- Deceleration=2000000
-- Velocity=25000
-- Jerk=0

-- Retrieve the table of move profiles.
local moveProfiles = XAxis.NamedMoveProfiles
-- The structure of the moveProfiles table will be:
-- {
--     XAxisHomingProfile = {
--         Acceleration = 2000000,
--         Deceleration = 2000000,
--         Velocity = 1000,
--         Jerk = 0,
--     },
--     XAxisMoveProfile = {
--         Acceleration = 2000000,
--         Deceleration = 2000000,
--         Velocity = 25000,
--         Jerk = 0,
--     },
-- }

-- The profiles can be iterated through with pairs() (note the nested loops).
log.info("XAxis Move Profiles:")
for profileName, profile in pairs(moveProfiles) do
    log.info("  " .. profileName .. ":")
    for paramName, param in pairs(profile) do
        log.info("    " .. paramName .. ": " .. tostring(param))
    end
end

-- The output with the above configuration would be (iteration order not
-- guaranteed):
-- XAxis Move Profiles:
--   XAxisHomingProfile:
--     Acceleration: 2000000
--     Deceleration: 2000000
--     Velocity: 1000
--     Jerk: 0
--   XAxisMoveProfile:
--     Acceleration: 2000000
--     Deceleration: 2000000
--     Velocity: 25000
--     Jerk: 0
